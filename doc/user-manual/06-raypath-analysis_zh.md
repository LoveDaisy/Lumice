# 光路分析

「Raypath Analysis」窗口回答的问题是：「天空某个区域的光，是由哪些光路做出来的，各占多少」。
与主预览不同，它不产出画面——点击 Analyze 会发起一轮**专用、不渲染**的运行，按完整光路给每条
光线分组，并报告每一组占总能量的比例。

> **文档得先有过一张图，但不必是当前这份配置的图。** Analyze 提交的是面板上当前的文档——与按 Run
> 会渲染的场景完全相同——所以带着渲染图打开的 `.lmc`、上次运行后又改过的文档都可以直接分析（后者
> 屏幕上的画面是改前那份配置的，按钮下方会有一行提示「Image is from a previous configuration…」；
> 列表描述的始终是当前配置的场景）。它不做的是分析一个你从没见过渲染结果的场景：新建文档、导入
> JSON、或没有存图的 `.lmc`，Analyze 与 **In frame** / **Point** 两个区域档位都保持禁用（tooltip 提示
> 先按一次 Run），直到第一次 Run。除此之外，唯一会让按钮禁用的是正在进行的运行。

## 1. 面板在哪

分析工具住在 **Analyze 工作区**里：点击顶栏 **Render | Analyze** 双格切换的 **Analyze** 格
（当前模式高亮；点击另一格即切过去）。窗口随即从渲染布局换成 Analyze
布局——左边是场景编辑器，中间和右边是分析：**场景全景**（已提交的画面重投影成等面积全天圆盘，
区域控制与锥形点选都在它上面）在上，其下是本章描述的**份额列表**，右下角是类概览，左下角是
光路视图。两个工作区共享同一份场景文档和同一批编辑器；旧的浮动「Raypath Analysis」窗口已退役
——它做过的所有事现在都在工作区里完成。

## 2. 选取分析区域（ROI）

**Region** 一行提供三档：

| 档位 | 分析范围 |
|------|---------|
| **Whole sky（全天）** | 场景里射出的所有光线，不做任何空间筛选。 |
| **In frame（可见区域）** | 只统计落在当前画幅内的光线（与预览用的同一套镜头/视角/可见范围/正面判定）。选这一档需要文档渲染过一次（只加载了背景照片不算）；已选中而预览不在时，画幅取文档自身的视角与模拟分辨率。 |
| **Point（点）** | 以一个方向为中心的锥形邻域，在场景全景上显示为一个标记点（Render 工作区的渲染预览上也投影显示同一方向）。与 In frame 一样，要等文档有过第一张图才能选。 |

**Point 标记点**：切到 Point 模式时，标记点默认放在当前视角的正中央（前提是屏幕上有预览，且
之前没有留下一次点选的位置）。它每一帧都随视角重新投影，而不是钉在某个屏幕位置上——转动或
平移视角时它不会被落下。把鼠标悬停在它上面会变成手形光标，直接拖动即可把中心移到新位置；
**Pick on preview** 旁边显示的高度角/方位角读数会随拖动实时更新。也可以改按 **Pick on preview**：
窗口顶部会出现一条提示条（"Click on the preview to set the centre — Esc to cancel"）并把光标
换成十字线，在预览上任意位置点一下即可把标记点移过去，或按 Esc 取消。标记点、半径环和十字线
都画在预览本身上，所以任何压在预览上方的窗口——分析窗口、条目编辑器——会把它们盖住，而不是被穿透。

只要有了中心，**Radius** 滑杆就可以拖动——甚至在按 Analyze 之前也可以。在还没有结果时，拖动它
只改变预览上那个 ROI 圆环的大小；有了结果之后，它改变的是报表把能量加到锥心多远处，同样
**不会重跑分析**：底层这一轮统计本来就会把整个锥按细密的角度环记录下来，滑杆只是在显示时决定
加到第几环为止。也就是说，点一次 Analyze 之后可以反复来回拖滑杆，即时看到不同半径下的结果。

## 3. 发起分析

Analyze 按钮上方的 **Infinite rays** 与 **Rays(M)** 决定分析要跑多少光线——这是它自己的预算，
与文档的 **Rays** 设置相互独立（第一次打开窗口时会取该值作为初始值）。关掉 **Infinite rays**
并拖动 **Rays(M)**，可以让分析按一个固定的总数（单位百万，覆盖所有波长）跑；打开它则会一直跑到
你按 Stop 为止。任何区域档位下都没有单独的提前停止设置——光线预算与 Stop 按钮是运行结束的
唯二方式。

分析跟随 Settings 里的 `sim.ray_allocation`（默认 `adaptive`，可切到 `proportional`）——与渲染共用同一个
设置（`configuration.md` 里的 `scene.ray_allocation`）。取 `adaptive`（默认）时每次 Analyze 都按各晶体
实测的单光线能量方差、而不是按人口占比分配光线，且每次按下按钮都重新开始测量：报出的 Energy 占比两种
设置下期望值相同，但落在低占比晶体上的稀有光路会分到多得多的光线，那一行的噪声因此小得多（一个占比
100 / 100 / 0.2 的三晶体场景里，一百万光线下稀有行的噪声约低十倍）。取 `proportional` 时分析按人口占比
分配，这是可复现的对照口径。

点击 **Analyze**。一轮专用运行会遍历场景并按光路分组光线；运行中可以点 **Stop** 提前结束，
用已经攒到的数据出结果——按 Stop 不会丢弃已有结果，只是停止继续累积。跑完（或被提前停止）后，
下方的结果列表会填入内容。

**分析永远走 CPU**，即使你为渲染选的是 Metal 或 CUDA 后端也一样。这是刻意的设计，不是可以关掉的
降级：GPU 追踪路径不保留这个功能需要的逐光线记录。窗口里**没有**为此单独显示提示——Analyze 可能
比同一场景的 GPU 加速渲染慢一些，仅此而已。

如果配置在上一次运行之后又改过，Analyze 照样可用，报告的是改后的文档——屏幕上的画面还是旧的，
按钮下方那行提示会一直说明这一点，直到你重新按 Run。

## 4. 读懂结果列表

每一行是一条不同的光路——光线从起点到出射经过的完整晶体与面序列。穿过一个晶体的光路直接写
面序列：`3-5`（从 3 号面进、5 号面出）。若某个散射层里有多种晶体，则在前面标出晶体。多次散射时
每一层各自带括号、层与层之间用箭头连接，从根层开始：`(3-5) -> (1-3)`，或两层各自标出晶体的链。
**屏幕上**晶体名就是晶体卡片的编号：`#2(3-5)` 是 **#2** 号卡的光路，层间连接符画成右箭头图标。
卡片编号是稳定的——删卡、拖拽重排都不会改其他卡的号——而且结果行的编号指向分析时那批晶体，之后
编辑文档也不会跟着变（列表会提示何时已过期）；重新 Analyze 后各行会重新对上同一批卡片。**文本
本身**——CLI 打印的、Export CSV 写出的、C API 交出来的——是交换拼写：`C1(3-5)`、
`C1(1-3) -> C4(3-5)`、ASCII ` -> `，编号按场景构建顺序计数。**Exclude this raypath** 生成的
filter 带着所点行的屏显名（`Exclude #2(3-5)`），但名字只是标签；filter 的行为由它装的面序列和
P / B / D 决定。各列含义：

| 列 | 含义 |
|----|------|
| **Raypath** | 该链的可打印名称，格式如上。 |
| **Energy** | 这条光路在当前区域总能量中的占比（百分比）。列表按此列降序排列。 |
| **Cumulative %** | 从第一行累加到当前行的 Energy 之和，方便一眼看出前几行合计占了多少光。 |
| **+/-** | 该行 Energy 占比的统计噪声，由计入这条光路的光线数按 1/√N 估计，避免尾部条目的小数字被误读成精确值。（光线数本身不展示：自适应分配下它是分配器*送给*该晶体的光线数，既不跟晶体占比成比例，也与该行的 Energy 没有固定关系。）如果这一行接管了某个能量小得多的条目腾出的位置（见下方「记录上限」），括号里还会显示它有多少能量可能其实属于那个条目。 |

一条光路的能量占比**不等于**它在画面上看起来有多显眼：随机朝向晶体产生的弥散、覆盖面很广的
弱光路，总能量可能高于一条集中、明亮的窄弧，因而在列表里排得更靠前。这个列表回答的是
「有多少光」，不是「多显眼」。

**能量占比在 2026-09 发生过变化，此前的数字不可直接比较。** 自那以后，晶体按自身对太阳呈现的
投影面积截获光线，而不再是每个被抽到的取向都截获同样多的光（见 `configuration_zh.md` 中
`ray_allocation` 之后的迁移说明）。分析与渲染追迹光线的方式完全相同，因此继承了这一变化：由正对
太阳的取向产生的行占比上升，由侧对太阳的取向产生的行占比下降；在同一层混合定向与随机取向晶体的
场景里，各晶体之间的相对占比也会移动。分析本身没有任何改动——变化之前记录或导出的占比是按旧的
加权算出的。分出的光线中有一部分（随机取向晶体约为一半）现在会在入射时被拒，因此同样光线数下每行的 **+/-** 比以前略大。

**记录上限。** 分析保留的是一个足够大但固定的不同光路数量——普通场景根本不会碰到这个上限——
而不是随光线数或散射层数无限增长。如果某个场景产生的不同光路确实超过了这个上限，列表底部会
出现一行灰色的 **other**：它是没能放进具名行的那部分能量与光线数，也正是它让 Cumulative % 列
在最后一行恰好到达 100。这一行永远不可选中，也不能被排除，因为它并不对应某一条具体的光路。
按钮下方的状态行会在发生这种情况时提示（"record full (N hits)"）；对本工具自带的参考场景以及
大多数实际配置，这种情况根本不会发生。

**对称性（P / B / D）**。列表上方的三个复选框决定哪些光路算作同一行。它们与 filter 编辑器的 P、B、D
指的是同样三个对称元（棱面旋转、底面反射、镜像），但这里只合并**物理上等价**的光路，使一行对应一个
物理类。规则晶体、随机取向下三个全开（默认）时，`3-5` 的六个旋转和它的镜像合成一行；关掉 D，镜像路径 `3-7` 会单独成行；关掉 P，每个旋转都各成一行。复选框只是请求：
每个晶体只按它的形状与取向真正具备的对称合并——Parry 弧 roll 锁定，即使开着 P，`3-5` 的各个旋转也
分开；板状晶体即使开着 B，`1-3` 与 `2-3` 也分开（条件见 [`../raypath/raypath-symmetry.zh.md`](../raypath/raypath-symmetry.zh.md)
§2b，filter 编辑器的 `(i)` 提示会说明某个晶体适用哪些）。filter 的 P / B / D 不同：它不论晶体如何都按面编号
重新标号，所以在这样的晶体上合并得比这里的一行更多（[`../raypath/raypath-symmetry.zh.md`](../raypath/raypath-symmetry.zh.md) §1.1）。这是**显示态**
的选择：分析记录的是未约化的每一条路径，切换复选框会立刻用手头的结果重新分组——不重跑、总量
不变，选中的行只要它的光路仍然是一行就保持选中（被并进别的行的光路则自然取消选中）。如果分析
之后又按过 Run，手头的结果就不能再重新分组了；窗口会提示列表当前按哪种对称显示，下一次
Analyze 会应用复选框的设置。

**搜索**。对称性那一行与表格之间的搜索框把列表收窄到光路文本包含所输入内容的那些行，不区分
大小写，两种拼写都匹配：交换文本——ASCII 的 ` -> ` 连接符、`C1(` 的晶体前缀——所以从 CSV 或
命令行输出里照抄下来的任何片段都能定位到它的行（`3-5`、`C2(`、`->` 即所有多层光路、`-> (1-3)`）；
以及屏显拼写——`#2(` 能按卡片编号找到同一行。
它只是列表的一种看法，不是另一张列表：隐藏行不会改变任何数字。Energy 列仍然是每一行在整个区域
里的份额；仍然显示的行，它的 **Cumulative %** 仍然表示「到**整张**列表的这一行为止的累计」，被隐藏
的行照样计入——不会按你看得见的行重新求和，所以最后一个显示的行可能远不到 100。**other** 行不是
光路，搜索框非空时就不出现。被搜索隐藏的选中行仍然是选中行（Exclude 照常对它生效），清空搜索框后
一切恢复。Export CSV 导出的是整张列表，不是屏幕上的那几行。搜索文本在 Analyze 和 Revert 之后都
保留——它描述的是你怎么读结果，而不是哪个结果；打开或新建另一个文档时会被清空。

**复制一行**。在某一行上右键有两个菜单项。**Copy raypath** 把这条光路的文本原样放进剪贴板——ASCII 的
` -> ` 连接符，而不是行里画出来的箭头——贴到 filter、搜索框或笔记里就是 CSV 与命令行打印的同一串文本。
**Copy row** 把整行按 CSV 自己的形式放进去：`Raypath,Energy,Cumulative %,+/-`，逗号分隔，与 Export CSV
写这一行时用的是同一套格式化，所以复制一行与导出的文件逐字节一致。

## 5. 「Exclude this raypath」（排除此光路）与「Export CSV」

选中一行，点击 **Exclude this raypath** 会生成一个过滤器，恰好剔除这一行合并进来的那些路径，不多不少，
并把文档标为已修改。若在列表当前的对称位下，filter 自身的 P / B / D 覆盖的正好是这些路径，过滤器就带上这些位、
写这一行的光路；若会覆盖更多（晶体的形状或取向缺少该对称，这一行比 filter 的面编号族小），过滤器就不带对称、
把这一行的每条路径各写成一个备选，于是下方的 **excluded** 行会逐条列出它们——再按一次 Run 就能看到去掉它之后的画面。这复用的是在晶体编辑器里手动编辑
filter 的同一套机制，不是新发明的规则。

以下情况按钮会被禁用，并附带说明为什么：

- 没有选中任何行；
- **这条光路跨越了不止一个晶体**（对应多次散射的跨层链）——filter 挂在单个晶体上，今天没有
  办法表达「排除这条精确的跨晶体序列」。只有单晶体、单层的光路可以用这种方式排除；
- 这条光路经过的晶体已经不在当前文档里了（比如分析之后你改过晶体列表——重新跑一次再分析）；
- **用到该晶体的某个条目已经挂了一个 In filter**——Exclude 只会往 Out filter 上追加，所以这里
  按钮保持禁用；手动编辑那个 In filter，或把它的 action 改成 Out，才能继续。

如果该晶体已有的是一个 **Out** filter，按钮不会禁用：点击后会把这条光路作为又一个被排除的
选项追加进那个 filter——tooltip 会说明是哪个 filter、还有几个条目共享它——而不是被拒绝。
重复排除同一条光路不会产生重复项。

**已排除的行。** 下一次 Analyze 之后，被排除的光路会从结果里消失——那正是 filter 在干活——但
不会从列表里消失：它以一条置灰行留在结果行之下、**other** 行之上，标着 **excluded**，
让「到目前为止排除了哪些」摆在眼前，而不是靠记忆。这些行每一帧都从文档里读出来：第一个散射层的
每个晶体上、每个 Out filter 的每条光路各一行，拼写与结果行的屏显一致（`3-5`，该层有多个条目时
写 `#1(3-5)`，按卡片编号），不管这个 filter 是这个按钮写的、在晶体编辑器里手写的、还是随文件打开
进来的。只有
光路会这样显示；用编辑器另一套语法写的规则（`entry:2 & len:3`）不是光路，没有对应的行。而结果里
仍然列着的光路照常显示为结果行、绝不置灰——那说明 filter 没有生效（列表还没重新分析，或者是在
filter 不合并的对称性下读的），把它藏起来等于把这件事藏起来。**Energy** 列写着 `was 12.34%`：
你点排除的那一刻这一行的占比，只在本次会话里记着，并且只在与当时相同的 P / B / D 下显示——
其余情况（filter 来自文件、来自编辑器，或列表在别的对称位下读取）显示一个破折号。置灰行不计入
总量、没有累计占比、也不能被选中，所以 **Exclude this raypath** 永远不会以它为目标；搜索框和
右键复制对它与对普通行一样有效（**Copy row** 给出 `光路,excluded,<占比>` 三个字段）。置灰行
最后一列的 **↺** 按钮是 **Include again**（重新纳入）：把这条光路从它所在的 filter 里删掉——
若它是该 filter 的唯一一行，晶体就整个不再挂这个 filter——把文档标为已修改，并让这一行消失；
下一次 Analyze 之后这条光路回到列表里，下一次 Run 之后回到画面里。若晶体编辑器正开在那个条目上，
这一行也会同时从它的 filter 列表里消失。Export CSV 不写置灰行：文件是结果本身。

旁边的 **Export CSV** 把列表**按当前显示态**——当前半径、当前显示的 P / B / D 对称性、当前排序——
经保存对话框写成一个 `.csv` 文件。文件开头是若干 `#` 前缀的元数据行：导出时间、区域、Point 结果
的锥形中心 / 半径 / 累加环数、对称性、总光线数、百分比所对应的总能量、record full 命中数，因此
离开窗口也能自描述。然后是一行列头（`Raypath,Energy,Cumulative %,+/-`，与上方表格逐列
一一对应）和逐行数据：光路名、能量占比、累计占比、1/√N 噪声以及 **+/-** 列括号里的
接管上界（没有时留空），最后是 **other** 行（如果有）。数字
按原样写出——不带 `%`、不带千分位——方便表格软件或脚本直接读。没有结果时按钮禁用。

## 6. 类概览

选中一行后，右下角的 **Selection details** 卡片会在你继续工作的同时向引擎询问该类的信息：
查询在后台运行（运行中有一个 **Cancel survey** 按钮），卡片显示四种诚实状态之一——等待、
已取消、引擎的具名拒答（跨多个晶体的类会回答 `multi_layer_unsupported`，这是答案本身而非
错误），或完成后的概览。界面线程不算任何东西，也不编造任何东西：被拒答或未求值的部分显示
引擎自己的话。

完成的概览按该类的路由臂组织，先给少量主要结论，细节收在可展开块里：

- **方向恒等类**（每个姿态都把光送回太阳自己的方向）显示太阳处经认证的**源像**、**权重色偏**
  读数（如「偏蓝」）及其确切口径，以及「波长在这里不动任何边」的陈述——颜色问题是色偏，
  不是位移。
- **全维类**显示**支撑**（该类覆盖的偏折角范围）、几何可证时的**锐边**闭式证书、作为**有限
  分辨率探针读数**的亮度峰（与几何边分明），以及**色散块**：650 nm 与 450 nm 的内缘、二者
  相距多远、方向如何（经典双面 halo 是红内蓝外），其后是表里携带的每个其他 onset，以及依据
  ——引擎自己的几何串与证书的公式、顶角、交叉核对，全部就地可读。**权重颜色读数**、
  **权重色偏**与**参考剖面**（该类沿太阳径向线在文档参考波长下的亮度，空 bin 画成间隙而不是
  零）各自收在自己的展开块里。没有锐结构的类就如实渲染：一条支撑加一个探针读数，没有编造的
  「最亮点」。
- **家族受限类**（定向晶体）显示**冻结阶梯**：每一级冻结了哪个取向维度、中心与宽度是多少、
  每一级提出多少候选像、生存过滤器杀掉多少。
- **被拒答的类**用引擎的话说明——δ 轴无法对这个几何做划分，这是关于划分的陈述，不是该类
  无光——并在旁边保留可读的独立事实：**独立见证**（声明的源在该类上的正贡献事件）与
  **内反射份额**。

表头始终写明参考波长及其来源、位置读数所用的太阳，以及 survey 是否在预算内停止（partial
文档会说明）。选择另一个类会重新询问；卡片从不同时混着两个答案。

## 7. 光路视图（类参考图）

选中一行后，左下角的 **Raypath view** 区域画出该类自己的天空图——引擎的物理类参考图，一张
由该类**每一个成员**算出的单波长亮度圆盘（不是代表成员乘以成员数）。图和概览一样在后台到达，
区域如实标注自己的状态：等待、已取消、引擎的具名拒答，或图本身——外加更新中的 *refining*
注记（旧图留在屏上、锚定天空，绝不冒充最新答案）。

**怎么读。** 圆盘中心是你上次看的地方；黄点是太阳（图的零偏折点），细十字是天顶，浅弧是
地平。亮度是参考波长下该类每立体角功率的诊断色阶——不是场景颜色，图下方那行字写明确切口径：
波长及其来源、求值了该类多少成员（被预算截断的图会标注 *truncated* 并显示已完成的段）、采样数、
视图自身边界，以及引擎的几何依据。rank-0 类（方向恒等类）没有环可画：它的天空像就是太阳处的
点质量，画成琥珀色格并就地可读其测量质量——周围的暗格不是「无光」。

**怎么操作。** 拖动平移（天空跟随光标），滚轮以光标为锚缩放，**Fit** 框住图自身携带的分布，
**Full sky** 回到全天。每次视图变更都会就这个视图重新询问引擎——缩放是采样档位上的真实重求值，
绝不是旧栅格的放大——且请求会短暂合并，一次滚轮突发只问一次。λ 滑杆指定显式波长（每个波长
一次新求值；引擎不留 warm 图）；*reference* 回到文档自己的选择。**Overlays** 开关把 survey 的
可定位结论叠在图上：位置对象画成菱形，色散的两条内缘画成围绕太阳的红内蓝外一对圆并带各自
波长标注——曲线就是 survey 文档自己的值，画在它们属于的地方；没有位置载荷的 survey 什么都不
画，也不编造曲线。

**选点。** 在图上点一下（按下且未移动）即设定**天空点**——你要询问的方向——以白色十字标记，
可在盘上任意拖动，暗区也可以：选点是坐标，绝不是亮度阈值。图下方的 altitude / azimuth 输入框
不用图也能做同一件事（直接输入天空点的角度，方位角以太阳为 0），所以拒答或仍在计算的图绝不
妨碍命名目标。天空点与场景 ROI 相互独立：点图从不变更锥心或份额列表，在全景上指锥也从不挪动
你的天空点。

## 8. 点检视器（太阳方向球、光路 3D、点详情）

§7 回答的是「这个类在整个天空上长什么样」，由**天空点**供数的三个区域回答的是「这个方向上
正在发生什么」——而且三者各守各的空间：地图是方向，**太阳方向球**是晶体的姿态（太阳在
**晶体自身坐标系**里的方向——姿态空间的一个投影，不是姿态空间全体），**Raypath 3D** 区域则是
一条穿过晶体的具体光路。

**点详情**（右列、类概览之下）是锚。选定类、设好天空点后，引擎在后台就被询问这个确切方向
（秒级档位；点查询在同一 worker 上排在 survey 与 map 之后，等待时该块会说明，并有
**Cancel point** 按钮）。答案先给出引擎自己的回显——目标标签与偏折角、成员面序列、晶体、波长
及其来源、折射率、采样档位——然后是分量：把光送到你这点的那几条闭环或开弧姿态，各带端点状态
与覆盖度俱在的 fiber 积分（比如 48/48 点）。选一个分量，另外两个区域跟着它走。**点质量**答案
（方向恒等路径——太阳自己的像）按它本来的样子呈现：位置、与目标的分离角、轨道积分及其测度
支撑——没有 fiber、没有播放、没有被强拗出来的曲线。拒答自报家门；多层链报
`multi_layer_unsupported` 并指向既有退路（在 filter 里只保留这条链再重跑）。

**太阳方向球**画出所选分量的 fiber：每个有效样本是一个太阳在晶体中某处的姿态（`u` 箭头），
折线按顺序走过它们，高亮标记是当前样本。偏差网格（可开关）按每个太阳方向把光偏折到哪里给球
上色——只在文档携带网格时绘制，没有就缺席，绝不画成零。盘下方：权重条（每个样本的
ρ·A/a²·T·K——fiber 积分求和的那个量本身）、样本滑杆与 **Play**。拖滑杆或播放都在文档已返回的
姿态间移动；天空点本身从不动——播放改变的是你在看的姿态，不是你问的方向。

**Raypath 3D** 画出当前样本的真实路径：晶体线框（它的分析形状——分布摊平成引擎实际用的值）
配上来自引擎代表轨迹恢复的入射段、每一段内部反射与出射段，按颜色区分并带图例，接触点有标记。
**World** 与 **Crystal** 是同一条物理路径在两个坐标系里的样子（拖动转轨、滚轮缩放）。新姿态的
路径在算时区域会说明；无合法路径的姿态会说明原因（走廊的拒答及其测得的面积）；rank-0 点质量
没有路径，会如实说明而不是画一条。

## 9. 从命令行使用

同一个分析也是一个 CLI 子命令 `Lumice analyze`，写出的 CSV 与 **Export CSV** 对同一次运行保存的文件逐字节相同——两边走的是同一个格式化器，不是两份实现。config 只是场景；要问的问题全由选项给出、从不读 config，这正是它可脚本化、可复现的原因：

```text
Lumice analyze -f config.json                                          # 全天，输出到 stdout
Lumice analyze -f config.json --roi cone --center 43,0 --radius 2      # 以高度角 43°、方位角 0 为中心的 2° 锥
Lumice analyze -f config.json --roi frame --render-id 1 --csv out.csv  # 落进 render[] 条目 1 画幅内的光线
Lumice analyze -f config.json --symmetry none --rays 5M --seed 7       # 最细分组、自带预算、同机可重放
Lumice analyze -f config.json --symmetry none --chain-capacity 32768   # 记录上限放大到默认的两倍
```

`--roi sky | frame | cone` 对应面板的 Whole sky / In frame / Point；`--center <alt>,<az>` 用天空点的高度角与方位角给出锥心（方位角与太阳同一量法，所以 `--center <太阳高度角>,0` 就是太阳）；`--symmetry` 对应 P / B / D 复选框（默认 `PBD`，`none` 取最细分组）；`--rays` 对应窗口的 Rays 栏（默认用场景自己的 `ray_num`，包括 `"infinite"`）。两件窗口里没有对应物的事：`--seed <N>` 固定随机种子，让同一个问题的两次运行在同一台机器上是同一次运行（按契约，带种子的运行是单线程的；跨平台、标准库、ISA level 或 trace 后端时，同一种子给出的是统计等价结果而非逐位相同——见 [`../configuration_zh.md`](../configuration_zh.md) 「随机种子（`--seed`）与可复现性」）；一直跑的场景用 Ctrl-C 结束，结束时仍会写出到那一刻为止累积的结果。带 `--csv` 时文件每秒原子重写，脚本任何时刻读到的都是完整文件；不带时 CSV 独占 stdout，进度行走 stderr。CLI 没有半径滑杆：锥内所有环都被累加，文件头的 `cone_rings_summed` 行会如实写出。`Lumice analyze -h` 列出全部选项；另见 [`03-cli-quickstart_zh.md`](03-cli-quickstart_zh.md) §4。

**`--chain-capacity <N>`** 只为这一次运行设定 §4 所说的记录上限：最多保留多少条不同的、未归并的光路精确计数，超出的部分落进 **other** 行。默认 16384 就是窗口里那个固定值，装得下本仓所有参考场景；但用 `--symmetry none` 列出单个晶体的*全部*光路可能需要更多——仅六棱柱的 8 面光路就有约 29 000 条，默认值下它们正是 **other** 里的东西（文件头的 `record_full_hits` 行记的是有光路被拒之门外的次数，0 表示记录从未满过）。纯整数，不带 K/M/G 后缀，范围 1 到 1048576。代价是内存：追迹侧约 `workers × N × 220 字节`，列表侧再加一份量级相当的——32768 配 10 个 worker 约 140 MB，最大值要数 GB；`--workers` 手动开到自动值以上时第一项按比例放大。窗口里没有对应控件，窗口的记录上限始终是默认值。

**`--symmetry none` 列表里的已知噪声。** 凸晶体上一条光线不可能连续两次打到同一个面，所以像 `4-2-7-7-1-2-1` 这样的光路不是物理光路：这类行是光线擦过棱或顶点时的数值副产物，通常出现在结果尾部——能量打印为 `0.0000`、各只有一条光线（`+/-` 读作 100）。它们不影响真实行的能量占比，引擎也不过滤它们（在记录那一刻分辨「真的擦棱」与「舍入误差」是个尚未解决的问题，不是一条可以直接套用的规则）。做统计之前先把它们剔掉——面序列里有相邻重复面的任何行：

```python
import csv
rows = [r for r in csv.reader(open("out.csv")) if r and not r[0].startswith("#")][1:]
def repeats(name):  # any layer whose face sequence repeats a face consecutively
    for layer in name.split(" -> "):
        f = layer.split("(")[-1].rstrip(")").split("-")
        if any(a == b for a, b in zip(f, f[1:])):
            return True
    return False
clean = [r for r in rows if r[0] != "other (not recorded)" and not repeats(r[0])]
```

## 10. 从 CLI 读取路径特征报告

GUI 分析列表仍按 ROI 排完整光路的能量，目前不显示新的路径特征文档，也不把记录联动为预览中的可点击点。

```bash
Lumice raypath -f config.json --crystal 1 --path 3-1-5 --report --budget-ms 15000
```

schema 3 使用实际产品的 shape/取向/太阳盘/光谱、物理 L2 成员和同一份数值计算。证据分两层：
**几何层**在取向约化球面上枚举这条光路的结构对象（偏折角场临界集、可行域边界、透射权重折线、
受限族像），附精确证书（δ 轴 partition、端点 onset、可见性证书、色散裁定）；**MC 层**降级为
佐证（`mc_evidence`），可以支持或反驳结构对象，但既不晋升也不抹除。`features` 三桶
（`actual`/`candidate`/`unfinished`）由对象状态派生；枚举器实际产出哪些对象类别，
由文档的 coverage 行声明。不再按固定光路名字选择公式。内部 TIR 条件不自动代表实际蓝边；
色度条带是同一观察尺度下的两个水平，不是两个平滑尺度的位置包络。

这是配置光源下的条件光路诊断，不包含scene分配/filter权重或前级散射形成的入射场。

默认数值时限 15 秒，`--budget-ms` 可显式给到两分钟；光学和场求值的工作上限分别记录。
`--events` 控制外层样本，不是图像像素；省略时按成员与谱展开成本选择前缀。分析不绑定投影或 512² 图。
不传 `--wavelength` 时使用场景真实光谱；传入则显式选择诊断谱，并在报告中标明覆盖。
`partial` 文档可以包含独立可用的实际特征和候选；空数组不能证明物理上没有特征。
多晶体链明确不支持，单晶体内部反射仍支持。

`--target`、`--grid`、`--warm` 仍属未改变的目标点 fiber 流程，不能与 `--report` 混用。
位置、观察量、尺度响应、源事件范围的精确定义，以及 schema 2 → schema 3 的迁移说明见
[`../raypath/raypath-cli-output.md`](../raypath/raypath-cli-output.md) §7。

## 首版已知限制

- 诊断图与点查询运行在**参考波长、名义几何、点光源**口径上——它们有意不是 D65 场景画面，
  每条口径行都会写明。色散对是引擎固定的 650/450 nm 比较。
- 每个查询面各带自己的预算（survey 15 s、点 2 s、地图用自身默认）；被预算截断的答案保留已经
  建立的事实并说明自己是 partial——绝不用零补空，也不编造缺失的部分。
- 方向恒等（rank-0）类以**点质量**臂回答——没有 fiber、没有播放、物理上没有曲线就不强拗一条。
  近极与精确反日目标保留既有的具名拒答。
- 以下属已确认首版范围的后置项，不是退化：per-λ 彩色底图族、分离亮斑智能 Fit、手势中的连续
  细化、完整天空曲线（Parry/Lowitz）、全谱/日盘图、能量对照、反向拖姿态、任意姿态采样间插值、
  多层反解（沿用「filter 只保留这条链再重跑」的既有退路）。
- 地图是单圆盘等面积投影；太阳方向球是晶体姿态空间的投影，不是姿态空间全体。
