# 光路分析

「Raypath Analysis」窗口回答的问题是：「天空某个区域的光，是由哪些光路做出来的，各占多少」。
与主预览不同，它不产出画面——点击 Analyze 会发起一轮**专用、不渲染**的运行，按完整光路给每条
光线分组，并报告每一组占总能量的比例。

> **文档得先有过一张图，但不必是当前这份配置的图。** Analyze 提交的是面板上当前的文档——与按 Run
> 会渲染的场景完全相同——所以带着渲染图打开的 `.lmc`、上次运行后又改过的文档都可以直接分析（后者
> 屏幕上的画面是改前那份配置的，按钮下方会有一行提示「Image is from a previous configuration…」；
> 列表描述的始终是当前配置的场景）。它不做的是分析一个你从没见过渲染结果的场景：新建文档、导入
> JSON、或没有存图的 `.lmc`，Analyze 与 **In frame** / **Point** 两个区域档位都保持禁用（tooltip 提示
> 先按一次 Run），直到第一次 Run。除此之外，唯一会让按钮禁用的是正在进行的运行。

## 1. 面板在哪

点击顶栏里 **Colors** 按钮旁边的 **Analysis** 按钮（路径图标）。它会打开一个独立的非模态
「Raypath Analysis」窗口，可以和主预览同时开着——不会替换或嵌入任何现有面板。

## 2. 选取分析区域（ROI）

**Region** 一行提供三档：

| 档位 | 分析范围 |
|------|---------|
| **Whole sky（全天）** | 场景里射出的所有光线，不做任何空间筛选。 |
| **In frame（可见区域）** | 只统计落在当前画幅内的光线（与预览用的同一套镜头/视角/可见范围/正面判定）。选这一档需要文档渲染过一次（只加载了背景照片不算）；已选中而预览不在时，画幅取文档自身的视角与模拟分辨率。 |
| **Point（点）** | 以一个方向为中心的锥形邻域，在预览上显示为一个可拖动的标记点。与 In frame 一样，要等文档有过第一张图才能选。 |

**Point 标记点**：切到 Point 模式时，标记点默认放在当前视角的正中央（前提是屏幕上有预览，且
之前没有留下一次点选的位置）。它每一帧都随视角重新投影，而不是钉在某个屏幕位置上——转动或
平移视角时它不会被落下。把鼠标悬停在它上面会变成手形光标，直接拖动即可把中心移到新位置；
**Pick on preview** 旁边显示的高度角/方位角读数会随拖动实时更新。也可以改按 **Pick on preview**：
窗口顶部会出现一条提示条（"Click on the preview to set the centre — Esc to cancel"）并把光标
换成十字线，在预览上任意位置点一下即可把标记点移过去，或按 Esc 取消。标记点、半径环和十字线
都画在预览本身上，所以任何压在预览上方的窗口——分析窗口、条目编辑器——会把它们盖住，而不是被穿透。

只要有了中心，**Radius** 滑杆就可以拖动——甚至在按 Analyze 之前也可以。在还没有结果时，拖动它
只改变预览上那个 ROI 圆环的大小；有了结果之后，它改变的是报表把能量加到锥心多远处，同样
**不会重跑分析**：底层这一轮统计本来就会把整个锥按细密的角度环记录下来，滑杆只是在显示时决定
加到第几环为止。也就是说，点一次 Analyze 之后可以反复来回拖滑杆，即时看到不同半径下的结果。

## 3. 发起分析

Analyze 按钮上方的 **Infinite rays** 与 **Rays(M)** 决定分析要跑多少光线——这是它自己的预算，
与文档的 **Rays** 设置相互独立（第一次打开窗口时会取该值作为初始值）。关掉 **Infinite rays**
并拖动 **Rays(M)**，可以让分析按一个固定的总数（单位百万，覆盖所有波长）跑；打开它则会一直跑到
你按 Stop 为止。任何区域档位下都没有单独的提前停止设置——光线预算与 Stop 按钮是运行结束的
唯二方式。

分析跟随 Settings 里的 **Adaptive ray allocation** 设置——与渲染共用同一个开关（`configuration.md`
里的 `scene.ray_allocation`）。开启时（默认）每次 Analyze 都按各晶体实测的单光线能量方差、而不是按人口
占比分配光线，且每次按下按钮都重新开始测量：报出的 Energy 占比两种设置下期望值相同，但落在低占比晶体上
的稀有光路会分到多得多的光线，那一行的噪声因此小得多（一个占比 100 / 100 / 0.2 的三晶体场景里，
一百万光线下稀有行的噪声约低十倍）。关闭时分析按人口占比分配，这是可复现的对照口径。

点击 **Analyze**。一轮专用运行会遍历场景并按光路分组光线；运行中可以点 **Stop** 提前结束，
用已经攒到的数据出结果——按 Stop 不会丢弃已有结果，只是停止继续累积。跑完（或被提前停止）后，
下方的结果列表会填入内容。

**分析永远走 CPU**，即使你为渲染选的是 Metal 或 CUDA 后端也一样。这是刻意的设计，不是可以关掉的
降级：GPU 追踪路径不保留这个功能需要的逐光线记录。窗口里**没有**为此单独显示提示——Analyze 可能
比同一场景的 GPU 加速渲染慢一些，仅此而已。

如果配置在上一次运行之后又改过，Analyze 照样可用，报告的是改后的文档——屏幕上的画面还是旧的，
按钮下方那行提示会一直说明这一点，直到你重新按 Run。

## 4. 读懂结果列表

每一行是一条不同的光路——光线从起点到出射经过的完整晶体与面序列。穿过一个晶体的光路直接写
面序列：`3-5`（从 3 号面进、5 号面出）。若某个散射层里有多种晶体，则在前面标出晶体：`C1(3-5)`。
多次散射时每一层各自带括号、层与层之间用 ` -> ` 连接，从根层开始：`(3-5) -> (1-3)`，层内有多种
晶体时写作 `C1(1-3) -> C4(3-5)`。（屏幕上列表把这个连接符画成一个右箭头图标；文本本身——CLI 打印
的、导出 filter 的名字、C API 交出来的——仍是 ASCII ` -> `。）各列含义：

| 列 | 含义 |
|----|------|
| **Raypath** | 该链的可打印名称，格式如上。 |
| **Energy** | 这条光路在当前区域总能量中的占比（百分比）。列表按此列降序排列。 |
| **Cumulative %** | 从第一行累加到当前行的 Energy 之和，方便一眼看出前几行合计占了多少光。 |
| **+/-** | 该行 Energy 占比的统计噪声，由计入这条光路的光线数按 1/√N 估计，避免尾部条目的小数字被误读成精确值。（光线数本身不展示：自适应分配下它是分配器*送给*该晶体的光线数，既不跟晶体占比成比例，也与该行的 Energy 没有固定关系。）如果这一行接管了某个能量小得多的条目腾出的位置（见下方「记录上限」），括号里还会显示它有多少能量可能其实属于那个条目。 |

一条光路的能量占比**不等于**它在画面上看起来有多显眼：随机朝向晶体产生的弥散、覆盖面很广的
弱光路，总能量可能高于一条集中、明亮的窄弧，因而在列表里排得更靠前。这个列表回答的是
「有多少光」，不是「多显眼」。

**能量占比在 2026-09 发生过变化，此前的数字不可直接比较。** 自那以后，晶体按自身对太阳呈现的
投影面积截获光线，而不再是每个被抽到的取向都截获同样多的光（见 `configuration_zh.md` 中
`ray_allocation` 之后的迁移说明）。分析与渲染追迹光线的方式完全相同，因此继承了这一变化：由正对
太阳的取向产生的行占比上升，由侧对太阳的取向产生的行占比下降；在同一层混合定向与随机取向晶体的
场景里，各晶体之间的相对占比也会移动。分析本身没有任何改动——变化之前记录或导出的占比是按旧的
加权算出的。分出的光线中有一部分（随机取向晶体约为一半）现在会在入射时被拒，因此同样光线数下每行的 **+/-** 比以前略大。

**记录上限。** 分析保留的是一个足够大但固定的不同光路数量——普通场景根本不会碰到这个上限——
而不是随光线数或散射层数无限增长。如果某个场景产生的不同光路确实超过了这个上限，列表底部会
出现一行灰色的 **other**：它是没能放进具名行的那部分能量与光线数，也正是它让 Cumulative % 列
在最后一行恰好到达 100。这一行永远不可选中，也不能被排除，因为它并不对应某一条具体的光路。
按钮下方的状态行会在发生这种情况时提示（"record full (N hits)"）；对本工具自带的参考场景以及
大多数实际配置，这种情况根本不会发生。

**对称性（P / B / D）**。列表上方的三个复选框决定哪些光路算作同一行——与 filter 编辑器用的是
同一套 P、B、D 对称（棱面旋转、底面反射、镜像）。三个全开（默认）时，`3-5` 的六个旋转和它的
镜像合成一行；关掉 D，镜像路径 `3-7` 会单独成行；关掉 P，每个旋转都各成一行。这是**显示态**
的选择：分析记录的是未约化的每一条路径，切换复选框会立刻用手头的结果重新分组——不重跑、总量
不变，选中的行只要它的光路仍然是一行就保持选中（被并进别的行的光路则自然取消选中）。如果分析
之后又按过 Run，手头的结果就不能再重新分组了；窗口会提示列表当前按哪种对称显示，下一次
Analyze 会应用复选框的设置。

**搜索**。对称性那一行与表格之间的搜索框把列表收窄到光路文本包含所输入内容的那些行，不区分
大小写。匹配的是上文写法的原始文本——ASCII 的 ` -> ` 连接符、`C1(` 的晶体前缀——所以从 CSV 或
命令行输出里照抄下来的任何片段都能定位到它的行：`3-5`、`C2(`、`->`（所有多层光路）、`-> (1-3)`。
它只是列表的一种看法，不是另一张列表：隐藏行不会改变任何数字。Energy 列仍然是每一行在整个区域
里的份额；仍然显示的行，它的 **Cumulative %** 仍然表示「到**整张**列表的这一行为止的累计」，被隐藏
的行照样计入——不会按你看得见的行重新求和，所以最后一个显示的行可能远不到 100。**other** 行不是
光路，搜索框非空时就不出现。被搜索隐藏的选中行仍然是选中行（Exclude 照常对它生效），清空搜索框后
一切恢复。Export CSV 导出的是整张列表，不是屏幕上的那几行。搜索文本在 Analyze 和 Revert 之后都
保留——它描述的是你怎么读结果，而不是哪个结果；打开或新建另一个文档时会被清空。

**复制一行**。在某一行上右键有两个菜单项。**Copy raypath** 把这条光路的文本原样放进剪贴板——ASCII 的
` -> ` 连接符，而不是行里画出来的箭头——贴到 filter、搜索框或笔记里就是 CSV 与命令行打印的同一串文本。
**Copy row** 把整行按 CSV 自己的形式放进去：`Raypath,Energy,Cumulative %,+/-`，逗号分隔，与 Export CSV
写这一行时用的是同一套格式化，所以复制一行与导出的文件逐字节一致。

## 5. 「Exclude this raypath」（排除此光路）与「Export CSV」

选中一行，点击 **Exclude this raypath** 会生成一个过滤器，把走这条精确路径的光线剔除掉——采用
列表当前显示所用的 P / B / D 对称，因此过滤器剔除的恰好是这一行合并进来的那些路径，不多不少——
并把文档标为已修改——再按一次 Run 就能看到去掉它之后的画面。这复用的是在晶体编辑器里手动编辑
filter 的同一套机制，不是新发明的规则。

以下情况按钮会被禁用，并附带说明为什么：

- 没有选中任何行；
- **这条光路跨越了不止一个晶体**（对应多次散射的跨层链）——filter 挂在单个晶体上，今天没有
  办法表达「排除这条精确的跨晶体序列」。只有单晶体、单层的光路可以用这种方式排除；
- 这条光路经过的晶体已经不在当前文档里了（比如分析之后你改过晶体列表——重新跑一次再分析）；
- **用到该晶体的某个条目已经挂了一个 In filter**——Exclude 只会往 Out filter 上追加，所以这里
  按钮保持禁用；手动编辑那个 In filter，或把它的 action 改成 Out，才能继续。

如果该晶体已有的是一个 **Out** filter，按钮不会禁用：点击后会把这条光路作为又一个被排除的
选项追加进那个 filter——tooltip 会说明是哪个 filter、还有几个条目共享它——而不是被拒绝。
重复排除同一条光路不会产生重复项。

**已排除的行。** 下一次 Analyze 之后，被排除的光路会从结果里消失——那正是 filter 在干活——但
不会从列表里消失：它以一条置灰行留在结果行之下、**other** 行之上，标着 **excluded**，
让「到目前为止排除了哪些」摆在眼前，而不是靠记忆。这些行每一帧都从文档里读出来：第一个散射层的
每个晶体上、每个 Out filter 的每条光路各一行，拼写与结果行一致（`3-5`，该层有多个条目时写
`C1(3-5)`），不管这个 filter 是这个按钮写的、在晶体编辑器里手写的、还是随文件打开进来的。只有
光路会这样显示；用编辑器另一套语法写的规则（`entry:2 & len:3`）不是光路，没有对应的行。而结果里
仍然列着的光路照常显示为结果行、绝不置灰——那说明 filter 没有生效（列表还没重新分析，或者是在
filter 不合并的对称性下读的），把它藏起来等于把这件事藏起来。**Energy** 列写着 `was 12.34%`：
你点排除的那一刻这一行的占比，只在本次会话里记着，并且只在与当时相同的 P / B / D 下显示——
其余情况（filter 来自文件、来自编辑器，或列表在别的对称位下读取）显示一个破折号。置灰行不计入
总量、没有累计占比、也不能被选中，所以 **Exclude this raypath** 永远不会以它为目标；搜索框和
右键复制对它与对普通行一样有效（**Copy row** 给出 `光路,excluded,<占比>` 三个字段）。置灰行
最后一列的 **↺** 按钮是 **Include again**（重新纳入）：把这条光路从它所在的 filter 里删掉——
若它是该 filter 的唯一一行，晶体就整个不再挂这个 filter——把文档标为已修改，并让这一行消失；
下一次 Analyze 之后这条光路回到列表里，下一次 Run 之后回到画面里。若晶体编辑器正开在那个条目上，
这一行也会同时从它的 filter 列表里消失。Export CSV 不写置灰行：文件是结果本身。

旁边的 **Export CSV** 把列表**按当前显示态**——当前半径、当前显示的 P / B / D 对称性、当前排序——
经保存对话框写成一个 `.csv` 文件。文件开头是若干 `#` 前缀的元数据行：导出时间、区域、Point 结果
的锥形中心 / 半径 / 累加环数、对称性、总光线数、百分比所对应的总能量、record full 命中数，因此
离开窗口也能自描述。然后是一行列头（`Raypath,Energy,Cumulative %,+/-`，与上方表格逐列
一一对应）和逐行数据：光路名、能量占比、累计占比、1/√N 噪声以及 **+/-** 列括号里的
接管上界（没有时留空），最后是 **other** 行（如果有）。数字
按原样写出——不带 `%`、不带千分位——方便表格软件或脚本直接读。没有结果时按钮禁用。

## 6. 从命令行使用

同一个分析也是一个 CLI 子命令 `Lumice analyze`，写出的 CSV 与 **Export CSV** 对同一次运行保存的文件逐字节相同——两边走的是同一个格式化器，不是两份实现。config 只是场景；要问的问题全由选项给出、从不读 config，这正是它可脚本化、可复现的原因：

```text
Lumice analyze -f config.json                                          # 全天，输出到 stdout
Lumice analyze -f config.json --roi cone --center 43,0 --radius 2      # 以高度角 43°、方位角 0 为中心的 2° 锥
Lumice analyze -f config.json --roi frame --render-id 1 --csv out.csv  # 落进 render[] 条目 1 画幅内的光线
Lumice analyze -f config.json --symmetry none --rays 5M --seed 7       # 最细分组、自带预算、可复现
Lumice analyze -f config.json --symmetry none --chain-capacity 32768   # 记录上限放大到默认的两倍
```

`--roi sky | frame | cone` 对应面板的 Whole sky / In frame / Point；`--center <alt>,<az>` 用天空点的高度角与方位角给出锥心（方位角与太阳同一量法，所以 `--center <太阳高度角>,0` 就是太阳）；`--symmetry` 对应 P / B / D 复选框（默认 `PBD`，`none` 取最细分组）；`--rays` 对应窗口的 Rays 栏（默认用场景自己的 `ray_num`，包括 `"infinite"`）。两件窗口里没有对应物的事：`--seed <N>` 固定随机种子，让同一个问题的两次运行是同一次运行（按契约，带种子的运行是单线程的）；一直跑的场景用 Ctrl-C 结束，结束时仍会写出到那一刻为止累积的结果。带 `--csv` 时文件每秒原子重写，脚本任何时刻读到的都是完整文件；不带时 CSV 独占 stdout，进度行走 stderr。CLI 没有半径滑杆：锥内所有环都被累加，文件头的 `cone_rings_summed` 行会如实写出。`Lumice analyze -h` 列出全部选项；另见 [`03-cli-quickstart_zh.md`](03-cli-quickstart_zh.md) §4。

**`--chain-capacity <N>`** 只为这一次运行设定 §4 所说的记录上限：最多保留多少条不同的、未归并的光路精确计数，超出的部分落进 **other** 行。默认 16384 就是窗口里那个固定值，装得下本仓所有参考场景；但用 `--symmetry none` 列出单个晶体的*全部*光路可能需要更多——仅六棱柱的 8 面光路就有约 29 000 条，默认值下它们正是 **other** 里的东西（文件头的 `record_full_hits` 行记的是有光路被拒之门外的次数，0 表示记录从未满过）。纯整数，不带 K/M/G 后缀，范围 1 到 1048576。代价是内存：追迹侧约 `workers × N × 220 字节`，列表侧再加一份量级相当的——32768 配 10 个 worker 约 140 MB，最大值要数 GB；`--workers` 手动开到自动值以上时第一项按比例放大。窗口里没有对应控件，窗口的记录上限始终是默认值。

**`--symmetry none` 列表里的已知噪声。** 凸晶体上一条光线不可能连续两次打到同一个面，所以像 `4-2-7-7-1-2-1` 这样的光路不是物理光路：这类行是光线擦过棱或顶点时的数值副产物，通常出现在结果尾部——能量打印为 `0.0000`、各只有一条光线（`+/-` 读作 100）。它们不影响真实行的能量占比，引擎也不过滤它们（在记录那一刻分辨「真的擦棱」与「舍入误差」是个尚未解决的问题，不是一条可以直接套用的规则）。做统计之前先把它们剔掉——面序列里有相邻重复面的任何行：

```python
import csv
rows = [r for r in csv.reader(open("out.csv")) if r and not r[0].startswith("#")][1:]
def repeats(name):  # any layer whose face sequence repeats a face consecutively
    for layer in name.split(" -> "):
        f = layer.split("(")[-1].rstrip(")").split("-")
        if any(a == b for a, b in zip(f, f[1:])):
            return True
    return False
clean = [r for r in rows if r[0] != "other (not recorded)" and not repeats(r[0])]
```
