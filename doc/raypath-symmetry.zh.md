# Raypath 对称性：P、B、D 过滤器开关

本文档说明 Lumice 过滤器 `symmetry` 字段背后的几何原理，涵盖 raypath 等价性的两类来源、P/B/D 三个开关的精确语义、每个开关所需的取向集体条件、D 的镜面推导以及对应的 GUI 行为。

**目标读者**：希望从晶体几何层面理解 filter 行为的进阶用户、内测圈友、未来贡献者。

---

## 1. 背景

Lumice 追踪光线穿越冰晶各面，并将光线路径记录为面编号序列（例如 `[3, 5]` 表示棱柱面到棱柱面的路径）。若两条几何上不同的光路产生相同的可观测晕圈图案，则称它们**等价**。

利用 raypath 等价性可以减少模拟器需要追踪的唯一路径数量：`ReduceRaypath` 将等价类中所有成员映射到唯一的典范代表；`ExpandRaypath` 做逆操作，从典范形式重新生成所有对称变体。

过滤器上的 `symmetry` 字段是一个位掩码，控制启用哪些等价关系。若启用了实际取向分布不满足的对称性，会将非等价路径混为一谈，导致模拟结果不准确。

---

## 2. 对称性的两类来源

### 2a. 晶体几何对称（D6h——固有）

六角冰晶属于 D6h 点群，包含：

- **C6**：绕 c 轴的六重旋转（60° 步长）
- **σh**：一个水平镜面（垂直于 c 轴）
- **σv / σd**：六个竖直镜面（交替穿过棱柱面中心和棱柱棱）
- 以及上述操作的组合（非本征轴、中心对称）

该几何对称是**固有**的——对任何冰晶均成立，与大气中的取向无关。

**但仅对规则形状成立。** D6h 是*正*六棱柱、或上下锥一致的六棱锥的对称群。配置可以描述更低的对称：
`face_distance` `[1, 1.2, 1, 1.2, 1, 1.2]` 只有三重轴（120° 旋转、三个竖直镜面）而没有六重轴；
`upper_h` / `lower_h` 或上下楔角不等则没有 σh。因此约化使用的是**开关请求的元素与晶体形状实际具备的元素之交**
，再与其取向集体允许的元素相交（§2b）——绝不多用。按形状不具备的元素合并，会把不等价光路并成一行：
在上面的三重轴棱柱上，P 曾把能量相差 2.4 倍的近面光路与远面光路合并。

这里的「形状」是晶体配置所抽样的形状*分布*（含 sync group），而不是某一个抽出的实例：六个 `face_distance`
由同一分布独立同分布抽取时保有全群，因为把一次抽样旋转一格就是另一次同概率的抽样。唯一推导是
`DeriveGeometricSymmetry`（`src/core/crystal.hpp`），每个 `Crystal` 都携带它（`GeomSymmetry()`），
分析列表的约化上下文也携带它；C API 经 `LUMICE_GetCrystalSymmetry` 暴露。数值比较使用闭式几何的相对容差。

面编号约定：

| 分组 | 面编号 |
|------|--------|
| 底面（顶/底） | 1（顶面）、2（底面） |
| 棱柱面（侧面） | 3–8（六个面，每面相差 60°） |
| 上锥面 | 13–18 |
| 下锥面 | 23–28 |

### 2b. 取向分布对称（集体——条件性）

形状的对称元只是给面重新编号；它映射到一起的两条光路携带相同的光，当且仅当**晶体集体**以相同权重持有这两种编号——即取向分布在该对称元下不变。每个对称元移动的是取向的不同部分：

- **P（绕 c 轴 60° 旋转）** 是**滚转角**的平移。成立 ⟺ roll 分布在 60° 平移下不变——在本引擎里即 roll 满圈 uniform。方位角不参与：Parry 弧方位角均匀、roll 锁定，点亮 3-5 而其 60° 像 4-6 全暗。
- **B（σh）** 把 c 轴反向：同一物理晶体倒过来编号，对应取向 (zenith, azimuth) ↔ (180° − zenith, azimuth + 180°)。成立 ⟺ **天顶角**关于 90° 对称**且方位角**在半圈平移下不变（实践中：满圈 uniform）。滚转角不参与。板状（zenith ≈ 0°）不成立——朝上的永远是面 1，1-3 与 2-3 完全不同；柱状（zenith ≈ 90°）成立，roll 锁不锁都一样。方位角非均匀的柱状同样不成立：实测 3-2 占 1.98%、3-1 为零。
- **D（一个竖直镜面）** 需要方位角 uniform 360° 且 roll 锚点为 30° 的整数倍，由锚点选定镜面（§4）。

**核心洞察**：P、B、D 不是单个晶体的属性，而是由 axis distribution 描述的**晶体集体**的属性；引擎只在各自条件成立处应用它们——在不满足的集体上勾选开关只是不起作用（少合并几行），绝不会错误合并。三个条件即 core 的 `detail::IsPApplicable` / `IsBApplicable` / `IsDApplicable`（`src/core/crystal.hpp`），所有 CPU 约化（filter、分析链 id、分析列表读时合并）共用，并以 `LUMICE_IsPApplicable` / `LUMICE_IsBApplicable` / `LUMICE_IsDApplicable` 暴露。

本节旧版把 P 系在「方位角均匀」上、把 B 系在「天顶角分布对称（板状晶体）」上。两条都不对，而且引擎对二者都没有条件：P、B 在任何集体上都会合并。

## 3. P、B、D 开关的精确语义

### P — C6 旋转等价

应用六角棱柱绕 c 轴的六重旋转对称。在 C6 下，每个棱柱面映射到下一个（3→4→5→6→7→8→3），底面和锥面相应旋转。

**启用条件**：滚转角 uniform 360°（§2b）——随机、板状、柱状取向成立；Parry、Lowitz（roll 锁定）不成立。方位角不参与。

**效果**：典范 raypath 使用最小面置换代表；六条旋转等价路径合并为一条。形状只有三重或二重轴时只用它具备的旋转；形状没有旋转对称时 P 无效（§2a）。

### B — 水平镜面（σh）

应用穿过晶体赤道的水平镜面。在 σh 下：

- 底面：1 ↔ 2
- 棱柱面 3–8：不变（它们横跨镜面）
- 上锥面 ↔ 下锥面：13↔23、14↔24、15↔25、16↔26、17↔27、18↔28

**启用条件**：天顶角分布关于 90° 对称（c 轴两端无偏好朝上）且方位角 uniform 360°（§2b）。随机、柱状、Parry 取向成立；板状、Lowitz（c 轴接近竖直）不成立。

**效果**：从顶底面入射的路径与从底底面入射的路径等价；上锥面路径与下锥面路径等价。仅在上下两半一致的形状上：上下高度或楔角不同的六棱锥没有 σh，B 对其无效（§2a）。

### D — 竖直镜面（σv 或 σd）

应用单个竖直镜面，其方向由 axis distribution 的**滚转角 mean** 决定。根据 roll mean，镜面可能是 σv（穿过两个相对棱柱面中心）或 σd（穿过两条相对棱柱棱）。

在 D 下，底面 1 和 2 始终固定。棱柱面按 §4 的 σ-by-roll-mean 公式映射。锥面遵循相同的棱柱映射。

**启用条件**：见 §4——另外形状本身须具备 §4 所选的镜面（§2a）。

## 4. D 的启用条件与 σ 推导

### 几何基础

在 Lumice 旋转链 `R = Rz(az−π) · Ry(−zenith) · Rz(roll)` 下，世界坐标系的竖轴 `(0,0,1)` 映射到晶体坐标系中的向量 `(cos roll, −sin roll, 0)`。该向量随 roll 增大，在晶体 XY 平面内旋转，以 C6 反向顺序扫过棱柱面：face 3 → 8 → 7 → 6 → 5 → 4 → 3（每 360° 一圈，或等价地每 180° 回到同一 σ 轴）。

当方位角均匀分布在 360° 时，集体平均对竖轴具有旋转对称性。若滚转角分布同时集中在某个特定值附近（或关于该值对称分布），则组合集体满足由 roll mean 决定的特定竖直镜面对称。

### 启用条件

当以下两个条件**同时满足**时，D 可以应用：

1. **方位角为 uniform 360°**：`az_dist.type == Uniform && az_dist.std ≈ 360°`
2. **滚转角 mean 为 30° 的整数倍**：`roll_dist.mean mod 30° ≈ 0°`
   （容差 ε ≈ 0.001°；不区分 roll 分布类型）

当 D 不可应用时，即使勾选了 D 开关，模拟器内部也会跳过该对称性归约——不会影响模拟结果，也不会报错。

### σ-by-roll-mean 公式

设 `mean` 为滚转角 mean（单位：度）。计算：

```
n = round(mean / 30°) mod 6       -- 所在 30° 扇区（0..5）
a = (6 − n) mod 6                 -- 镜面参数（0..5）
```

D 镜面对每个棱柱面的映射：

```
pri_idx     = face − 3            -- 0-based 棱柱面索引（0..5）
pri_idx_new = (a − pri_idx) mod 6
face_new    = pri_idx_new + 3
```

底面（1、2）和锥面位置指示位（1x / 2x 前缀）保持不变；锥面 13–18 和 23–28 采用与对应棱柱面相同的映射。

### 参考表

| n | roll mean（mod 180°） | a | 镜面类型 | 穿越 | 棱柱面固定 | 棱柱面互换 |
|---|---|---|---|---|---|---|
| 0 | 0° | 0 | σv | face-3 轴 | 3、6 | 4↔8、5↔7 |
| 1 | 30° | 5 | σd | 棱 3–8 | — | 3↔8、4↔7、5↔6 |
| 2 | 60° | 4 | σv | face-8 轴 | 5、8 | 3↔7、4↔6 |
| 3 | 90° | 3 | σd | 棱 8–7 | — | 3↔6、4↔5、7↔8 |
| 4 | 120° | 2 | σv | face-7 轴 | 4、7 | 3↔5、6↔8 |
| 5 | 150° | 1 | σd | 棱 7–6 | — | 3↔4、5↔8、6↔7 |

周期为 180°：n=0 与 n=6（roll=0° 与 roll=180°）产生相同的 σv（穿越 face-3 轴）。

## 5. 典型场景参考

在具备完整 D6h 的形状上，引擎对各取向族实际应用的元素（GUI 的轴预设再加两行）：

| 取向 | 方位角 | 天顶角 | Roll | P | B | D |
|---|---|---|---|---|---|---|
| 随机 | uniform 360° | uniform，满圈 | uniform 360° | ✓ | ✓ | ✓（此处 D 与 P 重合） |
| 板状（幻日） | uniform 360° | Gauss ≈ 0° | uniform 360° | ✓ | ✗（面 1 恒朝上） | ✓ |
| 柱状（切线弧） | uniform 360° | Gauss ≈ 90° | uniform 360° | ✓ | ✓ | ✓ |
| Parry | uniform 360° | Gauss ≈ 90° | Gauss，mean 0° | ✗（roll 锁定） | ✓ | ✓（σv 穿越 face-3） |
| Lowitz | uniform 360° | Gauss ≈ 0°，宽 | Gauss，mean 0° | ✗ | ✗ | ✓ |
| 非整倍 roll | uniform 360° | Gauss ≈ 45° | Gauss，mean 15° | ✗ | ✗ | ✗（15° 不是 30° 整数倍） |
| 任意，方位角非均匀 | Gauss | 任意 | 任意 | 视 roll 而定 | ✗ | ✗ |

说明：
- 当 roll 为 `uniform 360°` 时，D 能合并的 P 已经合并（集体具有完整旋转对称性）；D 与 P 同时启用无副作用，但多余。
- ✗ 表示该开关对这个晶体被忽略，不表示勾选它是错误：约化只是让这些行保持分开。开关按 filter 设置，条件按晶体判定。

## 6. GUI 行为

**D 复选框**：始终保持可勾选状态（不灰显）。复选框控制模拟器是否尝试应用 D 对称性归约；模拟器内部会校验启用条件，不满足时跳过 D。

**信息提示**：当当前 axis 配置不满足 D 的启用条件（方位角不是 uniform 360°，或 roll mean 不是 30° 整数倍）时，D 复选框右侧出现一个透明的 `(i)` 按钮。悬停时显示 tooltip：

> D applies when azimuth = uniform 360° and roll mean is a multiple of 30°.
> Current config does not meet this condition, so D has no effect.

这一设计遵循"弱提示"原则：用户保留控制权，不会被阻止勾选 D，但会被告知该开关当前无实际效果。

**P、B 提示**：roll 不是 uniform 360° 时在 **P** 旁、天顶角不关于 90° 对称或方位角非均匀时在 **B** 旁（§2b），出现同样的 `(i)` 按钮，各自询问引擎（`LUMICE_IsPApplicable` / `LUMICE_IsBApplicable`）。轴已经排除 P 时，P 的提示给出的是轴的原因，而不是形状的旋转步长。

**形状提示**：约化还要与晶体形状求交（§2a），所以 GUI 对 filter / 染色行所属晶体调用
`LUMICE_GetCrystalSymmetry`，并在以下情况给出同样的 `(i)` 按钮：形状只每 120° / 180° 重复（或完全不重复）时在
**P** 旁；上下锥部分不同时在 **B** 旁；轴通过 §4 条件但形状没有它所选的镜面时在 **D** 旁。各元素是否真正起作用
（`p_effective`、`b_effective`、`d_effective`）在 core 内判定，与约化做的是同一组求交。

**形状根本没有的面**：形状可以让某个面完全没有面积——`face_distance` `[2, 1, 2, 1, 2, 1]` 对面 3、5、7 就是如此。
filter 点名这样的面时，不论对称设置如何都匹配不到经过它的光线（形状自身的对称把缺失面映射到缺失面）。这一点只报告不修改：
加载场景时每个这样的面打一条 warning，Edit Entry 弹窗在对应 filter 行下方注明（`LUMICE_CouldCrystalHaveFace`，core 的
`CouldFaceExist`）。该检查对固定值与 uniform 形状标量是精确的，对其他分布无法确定，因此不报。分析面板的开关作用于整个场景，
不显示提示；每个晶体仍按自身形状约化。

## 7. 不在本设计范围内

以下内容 **不在** P、B、D 的覆盖范围内：

- **Complex filter 跨子过滤器的对称性**：`complex` 类型的过滤器组合多个子过滤器；跨子过滤器边界的对称性归约未实现。
- **含多值的 entry/exit 对**：当 `entry_exit` 过滤器列出多个入射或出射面时，P/B/D 之外的跨面对称性未处理。
