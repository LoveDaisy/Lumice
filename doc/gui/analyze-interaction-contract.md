## 1. 三个观察层（视图边界）

用户纠正后的认识（草图与讨论定稿，**静态草图**＋讨论定稿）：Analyze 的观察对象分三层，每层一个
有效展示与交互 owner；层的名称相似不代表输入层级相同——**Raypath view 属光路层；globe＋3D 属
天空点/姿态层；二者独立**。

| 层 | 视图 | 观察对象 | 所需选择 |
|---|---|---|---|
| 场景/画幅层 | 主工作区主视图 | 整个场景的画面与分析区域 | 场景；画面来自渲染 |
| 光路层 | Raypath view 窗 | 所选光路类的天空分布及相关特征 | 选定光路；无需先选天空点 |
| 天空点/姿态层 | 姿态/轨迹窗 | 姿态族投影、当前姿态、晶体内轨迹 | 光路＋天空点，且有适用的点结果 |

依赖方向：场景 → 光路 → 天空点/姿态，单向。每层内部的真实载荷表达（rank-0 点质量、空分量、
partial、拒答）见 §10——不为窗口统一而假造普通 fiber 或可播放轨迹。

## 3. 配置三分类

按生命周期三分类（机制层依据：field→tier，`gui-state-governance.md` §2/§10）。判据沿用讨论定稿
原则：是否服务于当前场景的调整、观察或分析；常驻性由使用频率与同屏需要决定，不因「有用」而平铺。

| 分类 | 内容 | Analyze 内形态 | 默认展开 | 可达入口 |
|---|---|---|---|---|
| **场景编辑**（sim-tier 文档） | Sun（高度角/直径/光谱）；晶体与滤镜（层/条目）；Rays/Max hits/GPU（渲染运行预算） | Sun 组就地展开可编辑；晶体/滤镜 = **入口行**（身份＋编辑入口），参数控件只在 Entry Edit；Simulation（渲染运行预算）= **默认折叠的就地编辑组**（同控件函数、同 id 语义；已落地） | Sun 展开；晶体列表展开；Simulation 折叠（打开即就地编辑，编辑仍走显式 Run 合同：kModified、无自动重跑） | Sun 滑条就地；晶体行点击开 Entry Edit（现路径：`analyze_workspace.cpp:104`→`panels.cpp:2095`→`panels.cpp:2077`，模态形态不变）；Simulation 折叠组就地 |
| **运行设置**（分析请求参数） | 区域选择、锥心、分析半径、分析 Rays 预算、Analyze/Stop | 主视图下缘操作条（已落地：区域两选＋半径＋Analyze/Stop＋Infinite rays＋预算 Rays(M)，宽单行/窄双行；Whole sky 下半径灰掉仍占槽，见 §15；锥心与运行读数进固定状态视口，列表对称/搜索先于新鲜度报告） | 操作条常驻（同档两 ROI 同高，见 §15） | 主视图下缘 |
| **观察/辅助线**（display-tier） | 镜头类型/FOV/视角/曝光/背景；辅助线组（网格/地平线/太阳路径/标注圆） | 左栏观察组；与 Render 共用同一显示状态源（§5.4），不新造第二套 | 镜头＋辅助线常用组展开；其余组折叠；折叠态会话内保留 | 左栏 |

**晶体入口与参数控件的区别表达**（验收约束）：左栏晶体行是**入口与身份**（一行一条目，点击开
Entry Edit、pick-link 语义沿用现列表行为 `analyze_workspace.cpp:80-112`），**不是**参数控件——参数
编辑发生在 Entry Edit 模态，这一分工与现状一致，合同不改变它。左栏行上不展开参数、不放缩略图与
逐行删除（那是 Render 卡片的 affordance，`analyze_workspace.cpp:74-76` 注释明确的边界，沿用）。

「就地编辑但不平铺」规则：Analyze 能就地完成「发现现象 → 改一个条件 → 更新结果」（Sun、观察参数、
区域与半径）；结构性深编辑（晶体/滤镜参数、渲染预算）走既有模态与 Render 工作区，不在 Analyze
平铺全部参数。

## 5. 主视图：观察交互、ROI 与取景连续性

### 5.1 主视图是什么

已提交渲染纹理的自由观察面：复用 Render 主视图的镜头族与辅助线体系，在既有全天数据上实时换镜头，
不触发重仿真（事实：镜头/视角是既有全天数据的实时显示，`doc/gui` 讨论与
`analyze_workspace.cpp:116-124` 的同源参数供给）。空态保留完整主图承载区，在区内引导「No rendered image for this document yet — press Run in the top bar」。
Analyze 工作区可以直接使用顶栏 Run；Analyze 本身仍要求文档已经展示过渲染结果。

### 5.2 手势分工（主视图）

| 手势 | 语义 | 条件与仲裁 |
|---|---|---|
| 空手拖拽 | 相机 orbit（grab 约定 = 项目唯一拖拽隐喻） | 新按压未归显式拾取、marker 或直接定位时 |
| marker 拖拽 | 移动锥心 | Point 模式且命中 marker（命中半径沿用 `kAnalysisConeMarkerHitRadiusPt`） |
| Alt/Option＋左键单击 | 直接设锥心 | Point 模式；macOS 显示 Option，其余平台 Alt；无武装步骤，marker 离屏也可用；图外/镜头无效区不改方向 |
| 滚轮 | 与 Render 同源的相机 FOV 缩放 | 每单位正 wheel 减 FOV 5°，钳制 `[1°, LUMICE_MaxFov(lens)]`；full-sky no-op，不解除 Look At Lock |

2026-11-06 手势修订：**已活跃显式拾取 > Alt/Option 定位 > marker 拖拽 > 相机 orbit**，仅在按下时
决定归属；持有到释放，中途改键、跨 marker、离图均不换臂。直接定位只写一次，无效点击也不回退 orbit。
已取得的相机/marker/直接定位按压不被后起显式拾取倒抢；Esc 或宿主消失停止动作但吞压至释放。
主图交互面尊重模态、浮窗与 display-mode control 的遮挡。Point 选项与 marker 悬停说明手势；旧 ROI
Pick 按钮、armed 状态、横幅和十字线整体退役，不影响晶体 share pick 或 Angular Distance。

两工作区实际调用同一个 `ApplyCameraWheelZoom`；输入归属仍留面内，Render 的 Alt/Option 照片缩放及
无可操作照片时 no-op 不变。手动画布沿用帧首 standing wheel claim：原生分发在 NewFrame，刚被滚入
指针下的首帧不再手动二次消费；主图外仍归控件/宿主，地图复用主相机缩放，3D保留姿态窗自己的缩放数量语义。显式拾取及
其吞拖 latch 期间不接管相机 wheel。上述操作均不 dirty、不重仿真、不自动 Analyze；ROI 结果仍对应
请求时中心，移动后提示显式 Analyze。

### 5.3 ROI：GUI 收敛为 Whole sky / Point

- GUI 的区域选择只有 **Whole sky**（全天空方向域）与 **Point**（锥形：中心方向＋显示半径）。锥形
  请求语义沿用现机制：请求总是全锥、按环切分，半径是显示期重求和，永不触发重跑
  （`gui_constants.hpp:197-211`、`analysis_panel.cpp:1456-1486`）。
- 区域语义是**天空方向域**，与镜头/画幅无关：换镜头、拖相机不重新解释已设区域
  （用户定稿方向）。Whole sky 与锥心方向都锚定天空方向，不锚定屏幕矩形。
- **In frame 移除的结构性理由**（验收指定结论）：In frame 的区域语义 = 分析时刻的当前画幅
  （DoAnalyze 取预览画幅或文档分辨率）。主视图获得自由相机后，「当前画幅」
  成为移动靶——同一区域定义被任何一次相机操作静默重解释，与上一条的方向域语义直接冲突。故 GUI
  移除 In frame；**CLI/C API 的 In frame 后端语义不动**（不删后端能力，scrum 规划约束）。
  当前侧证据：Point 单选由 HasEverShownPicture 门控
  （`analysis_panel.cpp` 的 region 段），移除后该门控只余 Point。
- 移除的连带：`LUMICE_RAYPATH_ROI_IN_FRAME` 相关的「画幅=点击时刻画幅」提示与画幅尺寸链路在
  Analyze 侧退役；契约级验证归实现片。

#### 5.3.1 退役记录（2026-11-05 实施裁决）

- **裁决**：owner 2026-11-05 实施裁决——**选项 A：本期退役 GUI In frame 入口**。
  依据＝scrum 755 规划判断的 owner 授权原文（GUI 收敛为 Whole sky/Point、保留 CLI/C API 能力）与
  本合同 §2.2/§5.3 的既有钉定；决策可逆（git 单 commit 可恢复入口）。

### 5.4 取景连续性

Render 与 Analyze 共享**同一份**取景/曝光/辅助线显示状态（display-tier 字段组单源；现 panorama
已从与 Render 相同的供给函数取参数，`analyze_workspace.cpp:118-121`）。用户可见行为：

- 切换工作区**不重置取景**——Render 调好的镜头、视角、辅助线在 Analyze 主视图原样呈现，反之亦然。
- 两个工作区都能改这些字段；在任一侧的修改立即反映到另一侧（同源，无第二套规则）。
- 取景连续性不覆盖分析请求参数：区域/锥心/预算是 Analyze 的会话态（现 tier 归类不变，
  `gui-state-governance.md` §10.2），Render 不展示它们。

### 9.3 初始比例与首次出结果后的变化规则

- 初始默认比例 = D2 建议值（列表 ≈ 45%，§4.2）。

  横幅——都不触碰 D1/D2。

### 11.2 核对结论

- 默认窗下全部区域容纳；最窄窗下全部区域**有条件容纳**——条件逐行注明（内部滚动/折行/说明折叠/
  下限规则），其中 R4 右列在 640×680 依赖「固定交互栈＋滚动状态区」的两段结构（globe 固定栈 123px
  +曲线区全形 330pt，均逐项可复算；640×420 时代的最窄面随 756 曲线区上调）。无一处需要把内容移出其 owner 区（§2.2 归属表成立）；最窄窗有效宽度按 §4.2 钳制规则
  复算（右列 260/主视图 464）。降级次序：说明类文字折叠 → 折行 → 内部滚动 → 压缩图形区下限，
  交互控件与操作条/输入行最后失守。
- 现四列布局在同一最窄窗已低于若干控件的可用下限（R2 行注：ROI 三选单行 208px > 158px 可用）——
  本合同的分区与折行规则是相对改善，不冒充「现状全部容纳」。
- 图形区下限（图面 160、globe canvas 60、3D 240×180）沿用现实现下限锚点，实现片校准时复核。
- 剩余未验证项：真实运行环境的 `CalcTextSize` 与字体文件 advance 的逐像素差、用户 UI scale ≠1x 下的
  行集、1.5x scale＋最小工作区的滚动退化——全部标注为**实现片渲染级校准义务**（§0 两层切分），
  不以本表冒充已完成。

## 15. 稳定空间合同（2026-11-06）

> §16 建议更换 map 右侧内容顺序与 Pose 区域 owner，但**不更换**本节的几何先行、可见 client、
> 单一分配 helper 与无失配旧数据规则。新边界D7是否采用另待owner裁决。

本节是 §3/§6/§7 的当前空间规则。§11 的带日期高度测量保留为前一形态的预算记录，
不再作为「结果文字在画布前、自然高决定画布」的实施配方。五处分隔、外窗下限与查询/物理语义不变。

- **几何先于内容**：相同窗口可见几何、UI scale 和分隔比例下，空态/等待/首结果/重试/partial/
  拒答/取消不移动画布承载矩形与主要操作锚点。可变内容只能在自己的报告中换行/内滚；不读上帧
  消息高度决定本帧画布。零高不传给 BeginChild（它意味着填满剩余区，而非没有区域）。
- **主图**：无纹理仍提交完整 picture child，Run 指引在其中；状态视口与操作带位于图下，操作贴底。
  宽档单行，窄档两行：第一行 Whole sky/Point、Radius、Analyze/Stop、Infinite rays，第二行 Rays(M)；
  Radius 紧随区域两选，Whole sky 下灰掉——禁用可见、仍占同档槽位（灰掉的是交互面，不是缺席：
  请求模式是 enabled 的唯一权威，Point 模式无论有无结果都可驱），两 ROI 同档同高不变。
  定档阈值是完整控制足迹（字形、frame、输入框、标签、间距）按该顺序的和，行需求消费控件的实帧
  步进（单源 `MeasureOperationWidths`；gui_test 校准腿以实测足迹 ±1pt 钉定档边界、±5pt 钉 Rays(M)
  轨道宽）。小到两行完整足迹也不能容纳时，操作带内部滚动，不产生水平滚动、不把预算或执行动作
  永久裁掉；最窄窗的实测边界账见 §11.1 R6。锥心漂移告警（分析完成后挪动锥心）是主图与
  状态视口之间的独立固定带（779.1）：高度按活字体与实际宽度实测换行，出现／消失只改变主图
  高度，不在状态视口的滚动流内，也不改分隔比例；其存在期间旧结果与动作照常。中心、rings、
  结果计数、截断、运行与旧图提示在固定高度状态视口；同时成立的事实分别保留，全文能内滚读取。
- **列表**：对称/搜索是稳定头；stale 和实际对称口径在其后独立状态视口，不插到搜索前。
  表格吸收中间份额，空结果保留该份额，Exclude/CSV 贴底。极端倍率只按几何把固定头移入可恢复内滚，
  不由 stale 文案决定是否滚动。
- **地图**：左侧 Overlays、方形 canvas、状态报告依次分配；waiting/retrying 不在 canvas 前加行。
  右侧先 λ/reference、Fit/Full sky、alt/az、Set/Clear、Pose & trace 入口与常驻 3D 用途/类＋天空点说明；
  后接身份/caliber/图例报告。入口的标签分行只按可见列宽决定；查询状态与报告滚动不改变其槽位。
  reference 与 Clear 不适用时保留禁用槽。cursor 仍是画布内非流式读数；地图在同身份 Retry 时保旧图，身份门不变。
- **Pose**：globe 的分量槽（单分量禁用、无分量诚实占位）、canvas、样本/播放槽常驻；无样本时禁用，
  不以 0 假装有样本。3D 的帧选择与 canvas 常驻，描述/partial/拒答/图例/transmittance 进报告。
  曲线的可变身份/积分/图例与读数也在报告；图仍保留五臂、对数轴、精确零行、不可用断线与同一游标语义。
  旧点/样本不匹配时只保留结构，绝不绘制失配旧内容。
- **可见区而非请求尺寸**：浮窗的名义下限可能高于实际 viewport。分隔应划分实际可见 client 区，
  而非一段自身 ScrollMax=0、祖先却已裁掉的不可恢复后缀；这不扩大外窗，也不放宽 canvas 四边包含。
- **真实复用边界**：`canvas_report_layout.hpp` 仅拥有几何分配与可见 client 区；map、globe、3D、曲线
  真实消费，同一语义只有一个实现。圆盘/3D/曲线的绘图、量纲与输入不进入该 helper；主操作分档独立。

自动化分别核对真实渲染矩形、实际输入/采纳、用户主动改变几何后的适配；数值 helper 不能替代成品
取证，测试通过也不代签人的观感判断。
