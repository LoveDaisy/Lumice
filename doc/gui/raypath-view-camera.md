# Raypath view：共享相机前的计算边界审计

> 状态：**取证记录，尚不是获准实施的共享相机蓝图**。源码基线 `c1149fe20`，核对日期 2026-11-06。
> 已批准的产品目标是 Raypath view 与主图同源镜头、同交互、双向同步，纯观察不启动新 scan。
> 本文先裁定现有数据能承载什么；不能从「物理分布定义在球面上」推导出「已有可无损换镜头的全天数据」。
> 当前实现合同仍是 [reference-map.md](../raypath/reference-map.md)；本文不追溯修改现有 C API。

### 1.1 五类操作的条件对照

| 操作 | 立即效果 | 后续实际工作 |
|---|---|---|
| Fit | 有采纳图且正值可拟合才写中心/半径；来自**当前图的格值**，不是全天结构支撑证书 | 若键变：先旧图重栅格，再 settle、新 map、重新采样/求值、采纳。无结果/全零/键不变不新发 |
| Full sky | 总是写天顶/180°并记用户 steering | 已处同一键时不新发；中心原来不同即使半径已 180°，键仍可变（请求实际上都映成全天，身份比请求域更细）。改变时仍走完整 map 路径 |
| 裸图拖拽 | 改圆盘中心，旧图按天空锚定重栅格 | 手势中不新发；停止并 settle 后若键变，重新采样/求值。marker 拖动是另一输入臂，只改天空点 |
| 滚轮 | 改半径/中心（最小半径 1.5°，`analyze_map_view.hpp:50`）；只有画布持有 wheel 且方向有效时消费 | burst 合并到 settle 请求；达到钳位且键不变不新发。信息区 wheel 是滚动，不是缩放 |
| 首次 auto-Fit | 首个采纳图、该选择未尝试、用户尚未 steering 才运行 | 成功改变键会发生第二次完整 map；Fit 失败或用户已动则不发第二次。换类恢复这条默认链 |

**分层结论**：当前同时存在真正的显示重投影、CPU 重栅格和完整物理重求值；三者不是同义词。
删除视窗键只能阻止后两者中的请求臂，不能生成被丢掉的事件或补足窄窗覆盖。
「重复点按钮不扫描」成立的条件是键未变，而非点击去抖保证任意两个全天请求都合并。

## 3. 现有载荷的保留与丢失

| 产物 | 保存了什么 | 不能推出什么 |
|---|---|---|
| 最终 `MapResult` / C map handle | 当前视窗格的中心坐标、per-sr 类和、事件数、状态、帧轴；完整成员前缀/λ/n；独立点质量 | 细格内事件偏折/方位响应、窄窗外数值；计数不包含事件本身 |
| `BandSum` 局部 `SampleEvent` 列表 | 每成员完整 lattice 的正 A·T、u、phi、偏折/序号，未按视窗裁剪 | 现在不留在 workspace/result；即使保留也未预计算所有天空方位的姿态密度 |
| GUI RGBA 圆盘 | 截断/着色后的最多 512² 显示像素 | 原始量、奇点/域外与零的可逆区别、细弧数据、全空间覆盖 |
| geometry workspace slot | 名义晶体几何与索引 | 波长相关光学事件、方向密度或已求出的 class map |

结构证据：`src/raypath/results/reference_map.hpp:64–76` 是最终数值载荷，
`src/analytic/discovery.hpp:335–349` 是更上游事件；两者不应混称「全天结果」。
`MapResult` 冻结与读取仍须服从 [typed-results.md](../raypath/typed-results.md) 的只读完成值原则，
不能把第一次 getter 的列拷贝扩成隐式补算。

## 4. 表示判别：已证边界与未决路线

### 4.1 格值的信息损失

`BandSumOnEvents` 的 band 值（省略相同的归一化常数）是
`sum(w_i * rho_i(az_center), delta_lo <= delta_i < delta_hi)`。
只保存粗格的值与 k，无法反推出移动/缩窄后的区间和：例如同一粗 band 内两事件，权重
`(1,3)` 与 `(3,1)` 都给总和 4、计数 2，但只含第一个事件的新窄 band 分别给 1 与 3。
这是算子的非单射反例，**不是声称这两张小表来自 C01 的光学事件**；第 2 节的真实 C01
内缘读数独立说明细窗带来的空间分辨能力不是虚构。把旧全天格插值或把旧窄窗域外填零均不合格。

当前 GUI 最小直径 3° / 220 格，偏折步长约 0.013636°。若用同一步长的全天等角表，需
13200×26400 = **348480000 格**；仅一个 double 值列为 **2.596 GiB**，按现有三 double＋
int＋enum、假定 32 B/cell 的裸 cell 表为 **10.386 GiB**，尚无 C 投影列、索引、GL 或临时空间。
这些是字段布局与整数算术**推导，不是 sizeof/RSS/性能实测**。它超出现接口 262144 格上限，
而且等角网格在极区过密，不能用此数字否定球面自适应/压缩方案。
即便如此增密，也只接近固定步长：新格边界连续移动会改变事件归属，固定表仍不与直接窄窗逐值相等。
所以「提高一张全天纹理的分辨率」既无现成载荷支持，也不是精度闭合证明。

### 4.2 保留事件的真实能力

`SampleEvent` 是与视窗无关的上游数据；保留它可避免再次 `BuildEvents`，因而避免新的
lattice、路径光学与入口面积计算。但它**不是已经加权完的全天亮度**：

- random/均匀密度 `rho=1`：排序偏折、权重的前缀和可查询任意 band，不必重新遍历光学事件。
  有理数区间算术的六个最小对照精确相同；这只证明代数分离，double 前缀相减会有消减误差，
  不能直接承诺 bitwise/细格相对误差或低正值保留。
- column/plate/Parry/Lowitz：`band_sum.cpp:201–206,232–254` 的 `RowsOf(event)` 与
  `PixelRow(sun, centre)` 共同决定 `rho`，方位变化会重新计算权重。
  `pose_density.cpp:175–183` 实际调用 acos/高斯，含 roll 家族再调用 atan2/周期高斯。
  因而一条只按偏折累加的标量前缀不能回答任意新方位。
- 代数见证：sun 高度 20°，事件正交基 F=I，column zenith90°/std1° 时，方位 90° 的
  未归一化密度为峰值 1，89° 为 0.6430673183545461，0° 在 double 下下溢为 0。
  公共密度归一化相消；这里同样是**核函数依赖的代数见证，不是引擎生成的物理场景或性能测量**。
  生产支持定向分布的证据来自 [C16](../cases/raypath-analysis-cases.md) 与源码，不能用 random
  成功代替定向家族的质量证明。`scene_to_analytic.cpp:186–201` 将声明的 spread 直接交给密度校验；
  合法 std 只要求有限且大于 0（`pose_density.cpp:63–75`），没有可直接借用的「所有密度至少有某个角宽」下界。

保留所有事件的体量也须具名：按现有字段推导 72 B/event，12 成员 n=500k 全保留上界约
412 MiB，n=2M 约 1648 MiB。**这是全保留计数上界，不是实际 kept/RSS**，也没有证明必须采用
该布局；辅助索引与 RowsOf 可使内存再增。旧完整查询时间不能证明事件重放的交互时延。

### 4.3 路线裁定

| 路线 | 已证能力 | 不能据此通过的条件 |
|---|---|---|
| 只删视窗 key／拉伸最终栅格 | 能停止重复请求 | 细弧、窄窗外覆盖及新 band 信息缺失，排除 |
| 更密的一张全天表 | 可事先规定固定角分辨率 | 现接口格数不够；移动 band 等价性/表示误差、极区与首算成本未证，不能冻结为推荐方案 |
| 保存全部事件，再调用 `BandSumOnEvents` | 可免新的光学采样；按相同 cells 重放可使用同一估计器 | 定向密度及 band 强度仍按视窗求值；不是只读显示重投影。不能把它改名「重栅格」宣告满足不重新求值的边界；实际重放延迟也未测 |
| random 的偏折前缀 | 存在可分离代数结构 | 尚无浮点细 band 误差/特殊态/交互实测；更不能覆盖现已支持的定向族。不以只支持 random 缩减目标 |
| 事件范围索引＋预计算方位响应的自适应/压缩表示 | 是继续保留目标的研究候选；查询可只读系数，不再评估物理密度 | **未证可行**：须控制窄密度/细 band 的累计误差与前缀消减、支持任意相机 footprint、首算/内存/每次观察成本。没有旧测量可复用，不以算法名称代替这些证据 |

本次执行了前三个算术判别与存储推导，没有运行新引擎请求、构建二进制或测量新方案时延。
这足以排除「现有结果只换投影」与「events 就是预先算好的全天亮度」两条捷径，
**不足以证明全部可能表示都不可行**。因此没有一条面向全部现有密度、保持细节且具备质量/成本证据的
推荐路线可以在此冻结；数据表示是未解前提，而不是可以留给产品实施临场定容差的细节。

## 5. 复用与诚实性：继续设计时不能丢失的边界

此处是研究路线的准入条件，不改变现有 API 行为，也不宣称目标表示已存在。

| 变化 | 可复用性/真正失效的依据 |
|---|---|
| lens、姿态、FOV、roll、visible/front、画布宽高/DPI | 不改变冻结场景的物理输入；合格表示应只派生显示。最终旧 map 却受原域/格限制，不能据此放大其有效范围 |
| 换类、成员展开/对称条件变化、名义几何或 λ/折射率变化 | 光学事件/成员和失效。选择身份必须含捕获场景与分析代，不能只比类行文字 |
| 朝向密度变化 | 旧带密度的全天表示失效；即使某些纯光学事件可复用，也须按真实类成员重新核定，不能复用旧 weighted field |
| 太阳方向或捕获场景变化 | 要重新核定帧、响应与类身份；不把 live 编辑后的太阳与冻结结果的太阳混用 |
| n/质量更新 | Fibonacci lattice 随 n 改变，旧事件不是新档的完整前缀；需要显式的新计算及新完成身份，不能在观察中偷补样本 |
| 分隔、关窗重开、工作区切换 | 本身不是数据变化；不能清查询绑定或重新计算。窗口开合也不应承载缓存寿命 |
| 预算/取消/迟到结果 | 不是新的物理场景，但改变已完成覆盖事实；只能使用有证据的完整成员前缀，不把中断成员混入，不将旧代结果以新相机缓存身份采纳 |

非有限/不可用不是零：finite zero、域外未知、奇点 NaN、拒答、partial 与 point mass 必须独立保留。
太阳/对跖附近的 band 奇点不能插值桥接。rank-0 质量 m 与方法/误差要单独保存；改变显示 cell 时
其 per-sr 值是 m/Omega，不是拉伸旧 cell 的数值，屏外质量也不等于质量为零。混合类不能只画质量而丢带状臂。
这些语义由 [reference-map.md](../raypath/reference-map.md) 的 Units/Execution 节承载，不能在 shader 里另造物理口径。

若未来证明新表示成立，物理数据仍归 engine/raypath，GUI 只通过 engine capability C API 消费；
不能从 GUI include `analytic/`/`raypath/detail/`，也不为一幅产品图另开库或绕过产品 API 直连 analytic
公开库。依据是 [analytic-api.md](../interfaces/analytic-api.md) §2 及项目 GUI 边界。
只读结果必须持有自身完成数据，borrowed 指针的有效期不能依赖已销毁的 Workspace/Scene，
参考 [typed-results.md](../raypath/typed-results.md) 的 Completion/Ownership 及
[capi-lifecycle-architecture.md](../interfaces/capi-lifecycle-architecture.md) §9 的独立持有原则。
保留/构造表示是显式执行，不放到 getter/序列化/换相机时隐式启动；此处没有新增 ABI 声明。

## 6. 设计暂停边界与待裁定项

**结论：现有载荷不充分已经有证据；完整目标尚未被证成，不是已证明不可能。**
不冻结共享相机的后续完整合同，也不把产品实施当成带未知精度/成本的探索。

已批准而继续保持的方向：唯一相机权威、双向同步、观察不 scan，不允许独立相机、手动 sync 或默认关闭开关。
既有相机输入是 `BuildPreviewViewProjFromRenderer`（`preview_renderer.hpp:481–496`）；有效 roll/front
规则、Look At 写入纪律仍服从 [gui-state-governance.md](gui-state-governance.md) §2。
主图不同宽高比使用同一 lens/FOV 规则，不要求画同一像素矩形。globe 的对跖中心、固定可视冠及有效 roll=0
